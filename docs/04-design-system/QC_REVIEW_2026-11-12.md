### Evidence and what to adopt

- **CFPB:** opening heading identifies tools for homebuyers; the body separates preparation, loan choices, offers, and closing. Adopt stage-based education and links to practical tools. The closing-scam panel intervenes before the process steps, so the next step is less immediate. Screenshot: `benchmark-cfpb.png` in the browser capture record.
- **Freddie Mac:** “Your guide to home” followed by buying, owning, refinancing, selling, renting, and help pathways. Clear short descriptions and large mobile link regions. Adopt purpose-based pathways, but preserve only the three pathways required for this site. Do not copy live rates or statistics. Screenshot: `benchmark-freddie.png`.
- **Habitat:** authentic paperwork image, task-specific title, Spanish-language path, and explicit local selection process. Adopt concrete consultation expectations and candid boundaries. The cookie panel obscured a significant portion of the captured mobile viewport; do not reproduce that obstruction. Screenshot: `benchmark-habitat.png`.
- **NACA:** concise program benefits, dated rate context, and explicit “Take Your First Step” action. Adopt clear action hierarchy and source dates, not program promises or rate claims. Dense offer/rate content dominates the initial mobile view. Screenshot: `benchmark-naca.png`.
- **Better:** visually distinct, labeled home-price, down-payment, term, and rate inputs; payment breakdown appears later in the snapshot. Adopt clear editable assumptions and readable results. Results are below the initial mobile fold. Do not adopt the lender’s pre-approval claims or copy-estimate URLs that could expose inputs. Screenshot: `benchmark-better.png`.
- **NerdWallet:** visible advertiser disclosure, field-specific help controls, differentiated loan-term choices, and explicit estimate language. Adopt contextual explanations and transparent assumptions. Two navigation layers and multiple rate choices make the mobile surface denser. Screenshot: `benchmark-nerdwallet.png`.

Fannie Mae’s YourHome site was also attempted but returned a Cloudflare verification screen. It is **excluded from scoring**, not counted as an inspected design.

### Proposed application to the controlled redesign

1. Keep the three buyer pathways concise, touch-friendly, and directly actionable.
2. Keep financial assumptions visible and editable; identify illustrative defaults as examples rather than current quotes.
3. Provide inline invalid-input guidance and suppress misleading outputs for invalid values. Preserve tested calculation formulas.
4. Use readable mobile result rows and an explicit “Discuss these estimates with Debra” action; never imply approval.
5. State consultation availability before collecting personal data. Verify actual delivery and fallback behavior against the latest implementation, not the stale branch.
6. Retain the currently approved visual direction until its latest authoritative record is inspected. The benchmark does **not** approve Navy + Amber or any replacement palette.

### Text-resize defect found and fixed

A manual 375×812 hosted-browser check at 200% root text size found calculator labels, inputs and validation errors extending beyond the panel and being clipped by its overflow boundary. The page itself had no horizontal scrollbar, so the existing viewport-overflow assertion did not detect this. The input grid's implicit minimum track measured about 561px inside a 197px content area.

The fix adds explicit `minmax(0, 1fr)` single-column tracks, zero minimum widths on field wrappers, safe long-text wrapping and wrapping secondary-action text in `calculator-ui.tsx`. `calculators-e2e.mjs` now exercises all five calculators at 200% text size on 375px screens and checks field/label/error bounds against the panel, not only page overflow.

After the fix, the hosted browser confirmed 32px input text, zero clipped fields, keyboard empty-input error/recovery, result-region focus, and unchanged desktop composition. Screenshots: `/tmp/agent-browser/pr50-fixed-inputs-200.png`, `pr50-fixed-results-200.png`, and `pr50-fixed-desktop.png`. This is a Chromium spot check, not a Safari/Firefox or screen-reader certification. The initial synthetic fill did not update React state; physical keyboard input verified the actual behavior. Type checking, zero-warning lint, all 262 tests, script syntax and diff-whitespace checks passed after this fix. The new CI regression run remains pending.
